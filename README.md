# LuckOfTheSea

A machine learning phishing URL detector: data pipeline, feature engineering, model evaluation, and a deployed API.

It only looks at the URL text (no page fetching). Each URL gets turned into 34 features, and I compare 6 models, from a baseline up to XGBoost and a character n-gram model that reads the raw URL. Data is split into train, validation, and test so no website shows up in more than one. The model and its threshold get picked on validation, and test is only scored at the end.

## Setup

Requires Python 3.10+.

```bash
git clone https://github.com/nuggetofwisdom/LuckOfTheSea.git
cd LuckOfTheSea
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest
```

## Usage

Run everything from the repo root.

```bash
python -m scripts.collect_data     # 1. pull phishing + legit URLs into data/raw/
python -m scripts.add_urls seeds/legit_logins.txt --label legit --source legit_logins   # optional, add my own url lists
python -m scripts.build_dataset    # 2. dedupe, cap per-domain, balance -> data/processed/dataset.csv
python -m scripts.train            # 3. train and compare models -> models/model.joblib, reports/
python -m scripts.predict "http://paypal.com.secure-verify.xyz/signin.php"   # 4. score URLs
```

The phishing feeds only list sites that are live right now, so run `collect_data` once a day for a couple of weeks to build up data. Each run writes new dated files. With two or more weeks collected, `python -m scripts.train --split time --cutoff YYYY-MM-DD` gives the most realistic test.

`predict` uses the threshold picked during training (about 1% false alarms on validation). Use `--threshold` to change it.

`data/` and `models/` are generated by these scripts and aren't committed.

## Project structure

```
phishdetect/
  features.py      URL -> 34 features, plus human-readable red flags
  model_io.py      save/load the trained model
scripts/
  collect_data.py  OpenPhish, PhishTank, Phishunt (phishing); Tranco + sitemaps (legit)
  add_urls.py      add my own list of URLs (like seeds/legit_logins.txt)
  build_dataset.py clean and balance the raw data
  train.py         train, evaluate, and save the best model
  predict.py       score URLs from the command line
seeds/             URL lists for add_urls.py
tests/             pytest suite for the feature code
```

`red_flags()` output for the phishing URL:
- Mentions a brand outside the real domain name
- Uses a top-level domain that's frequently abused
- Contains several login/verification keywords
- Not using HTTPS

The GitHub URL returned no red flags.

**Learned:**
- Models can't read text, only numbers. Each feature turns one question about the URL into a number, and the 34 answers together are the "feature vector" the model learns from.
- Each feature is a hypothesis about attacker behavior. The model decides how much each one actually matters.
- Browsers and users read domains left to right, so `paypal.com.account-verify.xyz` *looks* like PayPal. The real registered domain is the part right before the TLD: `account-verify.xyz`.
- `brand_lookalike` only catches typos like `paypa1.com`. This URL uses the real brand name in the wrong spot, which is a different trick caught by `brand_outside_domain`.
- The red flags are hand-written rules for humans to read, not the model's reasoning.

## Phase 4 · First training run, and a shortcut the model shouldn't have had

**Goal:** Train the models and sanity-check the winner.

**Did:** Trained on the domain split and scored a phishing URL and my own GitHub page:

```bash
python -m scripts.predict "http://paypal.com.secure-verify.xyz/signin.php" "https://github.com/nuggetofwisdom"
```

```

        PHISHING  100.0%  http://paypal.com.secure-verify.xyz/signin.php
                          - Mentions a brand outside the real domain name
                          - Uses a top-level domain that's frequently abused
                          - Contains several login/verification keywords
                          - Not using HTTPS (note: most phishing sites DO use HTTPS now)
        PHISHING   95.0%  https://github.com/nuggetofwisdom
```

**Problem:** My own GitHub page came back 95% phishing. To find out why, I looked at the dataset composition, the feature medians per class, the feature importances, and the test metrics:

```python
import pandas as pd
from phishdetect import features_dataframe, registered_domain

df = pd.read_csv("data/processed/dataset.csv")
print(df.groupby(["label", "source"]).size(), "\n")
df["reg"] = df.url.map(registered_domain)
print("github.com rows by label:", df[df.reg == "github.com"].label.value_counts().to_dict())

X = features_dataframe(df.url); X["label"] = df.label
print(X.groupby("label")[["url_length", "path_length", "path_depth", "uses_https", "num_query_params"]].median())
print("Legit URLs that are bare homepages:", f"{(X[X.label == 0].path_depth == 0).mean():.0%}")
print("Phishing URLs with path_depth <= 1:", f"{(X[X.label == 1].path_depth <= 1).mean():.0%}")
print("Legit URLs with path_depth == 1:", f"{(X[X.label == 0].path_depth == 1).mean():.0%}")
```

Top of `reports/feature_importance.csv`:

| Feature | Importance |
|---|---|
| `subdomain_length` | 0.252 |
| `num_query_params` | 0.073 |
| `num_subdomains` | 0.065 |
| `path_length` | 0.058 |
| `num_hyphens` | 0.057 |

| `tld_suspicious` | 0.055 |

| `num_hyphens_in_host` | 0.034 |

XGBoost test metrics (domain split, 8,657 train / 2,165 test): accuracy 0.919, precision 0.913, recall 0.932, F1 0.922, ROC AUC 0.973, **false positive rate 9.4%** (99 false positives).

**Diagnosis:** The #1 feature is `subdomain_length`. That's a red flag, since subdomains shouldn't matter that much. An even bigger red flag is the 9.4% false positive rate.

My best guess is that sitemaps list official `www.` URLs, so the model learned "has www = legit" instead of anything about phishing, which is also why a plain `github.com/nuggetofwisdom` looked suspicious. On top of that, 76% of my phishing URLs were only 0–1 folders deep, but only 14% of my legit URLs were exactly 1 deep, so short paths got lumped in with phishing too.

**Fix:** Strip `www.` before extracting features (with a test, `test_www_is_ignored`), and re-collect legit URLs spread evenly across path depths. I saved the old reports in `reports/v1-before-fix/` to compare after retraining.

**Results after retraining:**

| | Before | After |
|---|---|---|
| `subdomain_length` importance | 25% | 11% |
| `github.com/nuggetofwisdom` phishing score | 95% | 48.7% |
| False positive rate | 9.4% | 7.8% |
| Accuracy | 0.92 | 0.89 |

**Learned:** A high accuracy number can hide a shortcut. Accuracy dropped because the model lost a cue it never should have had, and the model is better for it.
